# Scenario 3 experiments

`scripts/` contains reusable launchers only. Local experiment inputs and outputs
belong here; runtime data is ignored by Git and must never be staged wholesale.

```text
experiments/scenario3/
  profiles/<run-id>/
    profile.json                 # reviewed paths, source/config hashes
    whole-target-request.txt     # only when --prompt-file was explicitly supplied
  runs/<run-id>/
    backup/                      # verified copies; originals are untouched
    project/
      skills/                    # exact builtin skill snapshot
      .kagent/                   # project intelligence/memory, journals, coverage,
                                 # observations, retained results/evidence
      artifacts/                 # runtime-generated evidence/reports/findings
    profile-home/.kagent/        # fresh personal intelligence/memory,
                                 # sessions/<id>.json, context/<id>.md, notes
    logs/                        # process/session logs
      headless/events.jsonl      # redacted events and terminal outcome
      headless/llm-metrics.jsonl # per-request usage/latency; no estimated cost
    launch-started.json           # exclusive single-launch marker
```

Raw provider credentials remain in the original API Config; manifests contain
only non-secret identity and its hash. Profile and run directories are created
exclusively after a reviewed `--prepare`; no existing experiment is overwritten
or deleted. Backup data stays outside the new Agent project root.

The default (v4) profile only isolates runtime data. It uses the normal KAgent
CLI with the configured provider/model, optional integrations, permissions,
and normal step defaults. It adds no wall timeout, HTTP grant/quota, token/cost
budget, vulnerability-class restriction, scanner restriction, or generated task.
The TUI opens with an empty draft unless a reviewed `--prompt-file` was supplied.

Example read-only planning command:

```bash
bash scripts/run_experiment.sh --dry-run \
  --run-dir /home/khainguyen/kagent/experiments/scenario3/runs/NEW_RUN_ID \
  --origin http://127.0.0.1:8081
```

Replace `NEW_RUN_ID` and the origin with the intended run name and authorized
lab origin. After reviewing the plan, use `--prepare --plan PLAN_JSON
--approve-plan-sha256 HASH`, then `--verify PROFILE_JSON` and `--run PROFILE_JSON`.
Preparation never starts Agent. Single-use profiles and pre-launch checks of
source/config/skills and fresh runtime directories remain in force.

`--max-steps N` is an optional native override; omitting it retains the normal
Config/runtime default. Other native CLI options can follow `--` on launch,
for example `--run PROFILE_JSON -- --browser` or `-- --model MODEL_ID`.
Target, session restoration, and output paths are managed by the launcher so
these options cannot redirect the run to old session/output data.

TUI `--yolo` follows ordinary CLI behavior and needs no extra launcher acceptance
flag. The normal runtime permission/scope/resource checks still apply. An
explicit native HTTP lab grant requires its ordinary acceptance flag. No grant
is generated by the isolation launcher.

Headless retains normal CLI requirements: supply a reviewed prompt at planning,
then launch with `--headless --execute-prompt`. Choose `--interactive` for POSIX
terminal questions/reviews (TTY required), or `--non-interactive` for fail-closed
input. Headless YOLO still requires an explicitly supplied finite native grant,
passed after `--`, and its ordinary `--accept-unknown-http-effects` flag. Normal
headless shell/bash/web-search restrictions are unchanged.

Configured skill paths are resolved against the original project; ordinary
personal/project playbooks and configured plugins/MCP remain available. This
is isolation of KAgent's learned stores and generated output, not a filesystem
sandbox or a filter on information an explicitly configured integration returns.

At step exhaustion headless saves `budget_exhausted` and stops. TUI Continue
starts another Agent turn; there is no same-turn resume API. This launcher
does not create extra turns or override native continuation behavior.

For reproduction of older bounded experiments, explicitly select
`--legacy-bounded` at dry-run. These v2/v3 profiles preserve the old reviewed
DeepSeek model restriction, 60-step default, generated SQLi/XSS task, and
20-minute wrapper timeout. Their YOLO acceptance and finite native-grant
behavior is also preserved. The old headless-shell preset is available only
with this explicit legacy mode. These limits are absent from default v4 profiles.

Offline verification logs may be stored under `runs/offline-verification-*`;
these are fixture tests, never Whole-target results. Earlier preflight evidence
under `.kagent/evaluations/scenario3-preflight-20261018/` is preserved unchanged
as a historical bundle, not imported into any new profile.
