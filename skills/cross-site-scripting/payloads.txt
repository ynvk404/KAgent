# XSS payload corpus for skills/cross-site-scripting/SKILL.md — two
# sections, matching the two payload-bearing stages of the actual
# workflow. This deliberately does NOT mirror sql-injection/payloads.txt's
# phase count: the two vulnerability classes have different workflows, and
# forcing XSS into the same number of phases would create sections with no
# real gate behind them. See SKILL.md "Workflow at a glance" and
# "Relationship to payloads.txt".
#
#   - Phase 1 (below): a plain-text DETECTION MARKER. Not executable. Used
#     only to observe where and how the input lands in the response
#     (encoded, inside a tag, inside an attribute, inside a script, etc.)
#     before any execution is attempted.
#
#   - Phase 2 (below): CONTEXT-SPECIFIC EXECUTION MARKERS. These attempt to execute
#     JavaScript when the returned context supports it. The safety property they carry
#     is that the *action* performed is harmless and self-contained
#     (setting document.title to a known value), not that they avoid
#     running code. Use only the entry matching the context you actually
#     observed in Phase 1 — do not try every context's entry against one
#     candidate.
#
# There is no Phase 3 or Phase 4 in this file. Stored XSS and DOM-based
# XSS are not separate payload categories. Stored probes use the Phase 2 entry
# matching the evidenced rendering context; DOM guidance below is recognition only.
# What differs is workflow (where the payload is submitted, when/to whom it
# renders back), which SKILL.md
# handles, not this corpus. Do not add a new phase section here without a
# corresponding ask_user-gated phase being defined in SKILL.md first.
#
# No browser-execution capability is available in the current runtime.
# Phase 2 markers establish an execution *hypothesis* from HTTP-level or
# source/sink evidence. When that evidence is not deterministic (e.g. a
# JS-string break-out, or a DOM sink whose actual execution can't be
# observed), SKILL.md requires recording `browser-required`
# and stopping — do not attempt to simulate or infer browser execution
# using shell, http, or any other substitute for an actual browser.
#
# None of these payloads exfiltrate cookies, tokens, or page content, and
# none chain into session hijacking, credential capture, keylogging, or
# redirection to an external site. They are absent from this default corpus;
# any separate controlled-impact path needs its own approval gate and
# supported runtime capability, as described in SKILL.md.

# ============================================================================
# ===================== PHASE 1 — CONTEXT DETECTION ==========================
# ============================================================================
# The baseline marker is plain text, without HTML/JS metacharacters. Its presence
# establishes input propagation only; the optional metacharacter probe below
# investigates transformations, not execution. Reuse adequate
# existing observations. Use the metacharacter probe only when encoding or
# transformation uncertainty remains; no extra detection request is required
# when adequate evidence already exists. Select the observed context's Phase 2 entry.

xsspoc{TIMESTAMP}                     # purpose: baseline marker with no special characters | applies: propagation/context not yet established by adequate observations | limit: establishes propagation only, not encoding or execution
xsspoc{TIMESTAMP}"'<>                 # purpose: marker followed by the four characters most output-encoding schemes transform (", ', <, >) | applies: unresolved encoding/transformation uncertainty | limit: observe which characters survive unescaped; still not an execution attempt

# Substitution is manual; read_payloads preserves placeholders and annotations.
# Payload lines exclude the alignment gap before "# purpose:" and indented notes.
# Replace {TIMESTAMP} with a fresh candidate suffix (actual runtime time if using
# epoch seconds; an otherwise unique inert suffix also works). Do not fabricate
# timestamps/session metadata. Reuse the candidate's chosen marker across its
# observations; a fresh candidate/run needs a fresh value to avoid stale matches.
# Illustrative substitution only, not a recorded timestamp: suffix demo7 gives
# full detection marker xsspocdemo7; {MARKER}=demo7 in Phase 2 produces title
# xsspoc-demo7. The suffix is demo7, not the full xsspocdemo7 marker. Preserve the
# respective prefixes; record exact input/title strings so observations stay linked.
#
# Read the response around the marker and classify the context per
# SKILL.md step 2 (html-body | html-attribute | js-string | url |
# html-comment | css-style-attribute | css-style-block | fully-encoded | unknown).
# Unknown remains unresolved; the list does not establish context. For URL/href/src
# contexts, inspect the HTML-decoded attribute value, scheme validation and
# canonicalization per SKILL.md step 2. HTML encoding alone does not establish
# safety in a URL or event handler; unknown handling is not a tested negative.
# Compare captured input and surrounding returned source for encoding, escaping,
# sanitization and truncation. Propagation, reflection, neutralized output,
# potentially executable syntax and observed execution are different facts;
# absence of HTML encoding is not confirmed execution.

# ============================================================================
# ============== PHASE 2 — CONTEXT-SPECIFIC CONFIRMATION =====================
# ============================================================================
# Select a harmless execution marker for the observed context. Use the entry matching
# what adequate captured observations showed. If executed, each sets document.title
# to xsspoc-{MARKER}, reading nothing sensitive and sending nothing off-session.
# Replace {MARKER} with the same suffix used for {TIMESTAMP} above, not the full
# detection marker. An unobserved title change does not establish execution failure.
# Inspect complete returned syntax and enclosing context, including Content-Type,
# inert elements and CSP, under SKILL.md steps 3/5. Deterministic HTTP proof remains
# sufficient when those conditions hold; missing necessary browser proof remains
# browser-required. Intended request syntax cannot replace captured response bytes.
# text/html fragments need no html/body wrappers. Raw reflection alone is
# not complete executable proof. If evidence shows deterministic removal of
# one trailing character, a grounded same-context adaptation can test it:
# append one inert trailing character to the selected execution payload, then inspect
# the returned complete syntax. Existing or new observations may justify further adaptation
# with a distinct prediction after a prior variant; there is no numeric variant cap.
# Avoid equivalent probes and payload spraying. Stop when evidence suffices, the
# hypothesis is adequately ruled out, no useful authorized test remains or execution
# is blocked by scope, permissions or runtime/operator limits. No additional phase,
# encoding trick or browser simulation is allowed.
# Failed variants support not-confirmed only after a completed bounded test with
# usable proof; missing browser execution stays browser-required, and missing
# required captures/proof stays insufficient-evidence (SKILL.md step 5).

# --- HTML body context --------------------------------------------------
<script>document.title='xsspoc-{MARKER}'</script>
    # purpose: direct script execution in an unescaped HTML body position
    # applies: ordinary HTML text between tags; not text inside textarea/title, a comment, template or another inert/incompatible context
    # limit: execution marker only — do not substitute a payload that reads document.cookie or similar

<img src=x onerror="document.title='xsspoc-{MARKER}'">
    # purpose: event-handler-based close variant for HTML body context
    # applies: captured source specifically shows script-tag stripping while other tags/attributes pass unescaped; tests that evidenced sanitization hypothesis, not an assumed execution failure or WAF bypass
    # note: src=x must actually fail image loading for onerror to fire; HTTP reflection alone does not establish that event or execution
    # limit: test the evidenced sanitization hypothesis; further adaptation needs a meaningful prediction from existing or new observations under SKILL.md's checkpoint, not arbitrary tag/attribute combinations

# --- HTML attribute context ---------------------------------------------
"><script>document.title='xsspoc-{MARKER}'</script>
    # purpose: break out of a quoted attribute value, then execute
    # applies: marker in Phase 1 rendered inside a double-quoted attribute, unescaped
    # note: the leading quote must close that actual value and > must reach an ordinary HTML parsing position; inspect the complete returned tag, suffix and any escaping
    # limit: match the observed attribute quote first; do not test both quote styles when it is known; apply SKILL.md step 5 if unresolved

'><script>document.title='xsspoc-{MARKER}'</script>
    # purpose: single-quote variant of the attribute breakout above
    # applies: same as above, for single-quoted attribute values
    # note: a quote inside an escaped value, inert enclosing element or incomplete returned tag does not establish breakout
    # limit: use for a supported single-quoted hypothesis; a failed double-quote probe does not settle an ambiguous delimiter, so reconsider existing source and predict the distinction

    # purpose: end an unquoted attribute's tag before the script
    # applies: unquoted value is observed or justified among competing delimiter hypotheses; inspect the entire returned tag and suffix
    # limit: tests that boundary, not every quote variant; enclosing context, policy and SKILL.md's deterministic proof conditions still apply

# --- JavaScript string context -------------------------------------------
';document.title='xsspoc-{MARKER}';//
    # purpose: break out of a single-quoted JS string literal, then execute
    # applies: marker in Phase 1 rendered inside a JS string (e.g. var x = 'MARKER';)
    # note: check the actual quote, backslash escaping, line breaks and surrounding source; HTTP echo alone does not establish a valid executable statement
    # limit: HTTP-level evidence of this succeeding is usually not deterministic — per SKILL.md step 3, record browser-required unless the response makes the break-out and execution position unambiguous

";document.title='xsspoc-{MARKER}';//
    # purpose: double-quote variant of the above
    # applies: same as above, for double-quoted JS string literals
    # limit: same browser-required caveat as above

${document.title='xsspoc-{MARKER}'}
    # purpose: expression substitution inside a JavaScript template literal
    # applies: evidenced backtick-delimited template source with an unescaped interpolation boundary, not an ordinary quoted string
    # limit: inspect complete surrounding source, backslashes and newlines; source reflection/parse acceptance alone is not execution, retain browser-required when needed

# --- URL / href / src context ---------------------------------------------
# Select this only when captured context supports a potentially executable scheme
# after HTML attribute decoding, scheme validation and canonicalization. An
# encoded attribute is not automatically safe; a verified safe-scheme restriction
# can neutralize this vector. Unknown handling remains unresolved; do not spray.
# An anchor href may require a click/navigation; an img src does not execute a
# javascript: URL as script. Element, attribute, trigger and policy must all fit;
# a javascript: string in an arbitrary href/src is not execution evidence.
javascript:document.title='xsspoc-{MARKER}'

    # applies: only for the evidenced scheme-capable element/context described above
    # limit: execution here typically requires a user action (click/navigation) to trigger — note this in evidence/notes; do not simulate a click via automation this skill doesn't have
